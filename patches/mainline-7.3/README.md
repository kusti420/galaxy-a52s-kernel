# Mainline track: changes on top of sc7280-mainline `sc7280-7.3.y`

Base: `https://github.com/sc7280-mainline/linux`, branch `sc7280-7.3.y`, commit `1cd0a2a93ac5`
(tag `v7.3.0-sc7280`). The tree is a git worktree of `linux/` at `linux-7.3/` (branch
`a52sxq-7.3`) and is not part of this repository. Recreate it:

    git -C linux fetch --depth 1 origin sc7280-7.3.y
    git -C linux worktree add -b a52sxq-7.3 ../linux-7.3 origin/sc7280-7.3.y
    git -C linux-7.3 am ../patches/mainline-7.3/*.patch

| patch | why |
|---|---|
| 0001 COMMAND_LINE_SIZE 4096 | the Samsung ABL appends ~3 KB (needed for any later real boot) |
| 0002 of/kexec alternative base FDT | `/sys/firmware/kexec_fdt`, same code as the proven ACK 6.18 harness patch (depth fix included); lets this kernel kexec a next one |
| 0003 machine_kexec `__nocfi` | kCFI fault on the physical-address jump (seen with ACK); no effect without CFI |
| 0004 a52ram earlycon | `earlycon=a52ram,0xf0be0000`, read back by the harness as `/proc/a52ram` |
| 0005 `sm7325-samsung-a52sxq.dts` + Makefile | the 6.18 harness board file unchanged, plus the QDSS nodes new in 7.3's kodiak.dtsi disabled |
| 0006 qcom_scm `gunyah_wdt=1` | the phone's hypervisor answers the Gunyah watchdog SMCs but its vendor-hyp UID call returns NOT_SUPPORTED, so upstream never registers the watchdog; `qcom_scm.gunyah_wdt=1` registers it anyway (the driver's probe still checks STATUS) |
| 0007 board base (M2) | regulators pinned to the downstream init voltages, ADC7 channels + ADC_TM zones, hall (SW_LID), gpio-vibrator, sdhc_2, ADSP/CDSP PAS with bare `adsp.mdt`/`cdsp.mdt`, fastrpc nsessions, `epss_l3` on the L3_VOTE (+0x90) descriptor, QCE disabled (interconnect sync_state) |
| 0008 dt-binding `samsung,s6e3fc3` | panel binding (vddi/vci supplies, reset, port) |
| 0009 `panel-samsung-s6e3fc3` | M3 part 1: DSC command-mode panel driver (60 Hz, normal brightness); init generated by `tools/dsi-cmd2c.py` from the downstream blobs |
| 0010 `sm7325-samsung-a52sxq-panel.dtso` | MDSS + DSI0 + PHY + panel as an overlay -> `sm7325-samsung-a52sxq-panel.dtb`; panel rails L8C/L13C at the panel supply entries 1.8/3.0 V; base dtb unchanged |
| 0011 dt-binding `st,fts5cu56a` | FingerTip 5 touch binding (avdd required, vdd optional, touchscreen.yaml props) |
| 0012 `stmfts5` input driver | M3 part 2: ST FTS5CU56A. New driver, not upstream `stmfts` (that is the FingerTip 4 protocol: 0x85/0x86 event reads, event id in byte 0, no echoes). Based on woa-a52s `stmfts_fts5cu56a.c` (6.15) with its bugs fixed (SMBus block reads > 32 bytes for multi-event FIFO reads, 0x39 = wake-up gesture sent instead of 0x30 touch type, no ready wait after the reset, no echo checks, endian-dependent bitfields, 496-byte stack buffer) and the vendor driver's power-on order (reset, ready, version/id, touch type, RAM-only force calibration, clear FIFO, scan on). No firmware update path |
| 0013 touch in `sm7325-samsung-a52sxq.dts` | I2C13 (QUP1 SE5) + GPI DMA 1 + QUP1 enabled, touchscreen@49, TLMM 81 level-low, AVDD L7C 3.0 V (downstream tsp_avdd_ldo), no vdd/reset; `tools/check-touch-dt.py` (run by `./build-mainline.sh`) compares it with the downstream node |
| 0014 `stmfts5` ic_status | Debug only, init sequence unchanged: root-only `ic_status` attribute (read-only register reads: version, id, panel info, touch types, opmode, CRC status, gesture-library mode; AVDD state; event counters by class + last event) and `debug=1` (logs it once at power on). Touch works without it (run ml73-t4) |
| 0015 `sm7325-samsung-a52sxq-gpu.dtso` | M3 part 3: Adreno 642L (0x06030500) + GMU as a third overlay -> `sm7325-samsung-a52sxq-gpu.dtb` (= base + panel + gpu; base and panel trees unchanged, GPU stays disabled there). Zap: bare `a660_zap.mdt` (own apnhlos), carveout = downstream; OPPs of the phone's speed bin 117 (315/450/550 MHz) with the downstream LPDDR4X DDR votes; `tools/check-gpu-dt.py` (run by `./build-mainline.sh`) compares regs/IRQs/SIDs/zap/OPPs with the downstream kgsl nodes |
| 0016 `sm7325-samsung-a52sxq-wifi.dtso` | M4: WPSS remoteproc (bare `wpss.mdt`, own apnhlos) + WCN6750 ath11k AHB as an overlay -> `sm7325-samsung-a52sxq-wifi.dtb` (= base + wifi); MSA TZ-owned (no wifi-firmware subnode); `tools/check-wifi-dt.py` compares with the downstream qcom,wpss / qcom,wcn6750 nodes. Works (ml73-w1) |
| 0017 `sm7325-samsung-a52sxq-bt.dtso` | M4 WIP: QUP0 + uart7 + qcom,wcn6750-bt (BT_EN 85, SW_CTRL 86, downstream rails) -> `sm7325-samsung-a52sxq-wifi-bt.dtb`; uart7 still needs a serial alias (probe -19) |

Not carried from `patches/ack-6.18` (not on this boot path): the of_iommu resv-region fix (for
the downstream vendor IOMMU DT only) and the SELinux `system:firmware_load` change (Android only).

`a52sxq-ml.config`: fragment on top of `fp5_defconfig` (`./build-mainline.sh` merges and checks
it; PAS, fastrpc, sdhci-msm, gpio-vibra are modules on purpose). `m2up.sh`: copied to the ramdisk as
`/extra/m2up.sh`, loads those modules in a running 7.3 session (`wdt sd vib dsp`; the DSP firmware is
read from the phone's own apnhlos, mounted read-only). `m3touch.sh` (`/extra/m3touch.sh [s]`): loads `stmfts5.ko`, prints the chip id / firmware version read at probe, runs the IRQ self-test (`i2cpoke`) and captures the touch events for s seconds, decoded by the static `/extra/evcount` (tools/evcount.c). `m3gpu.sh` (`/extra/m3gpu.sh [n]`, GPU tree only): mounts the own apnhlos (zap, `firmware_class.path=/fw/image`) and the own vendor (an extent of super through a read-only loop device; `/lib/firmware/a660_{sqe.fw,gmu.bin}` are runtime symlinks into it), checks all six firmware files against the sha256 read from the phone's own Android, reads the speed-bin fuse, loads the panel module (msm binds with the GPU), then runs `/extra/gputest` (tools/gputest.c: GET_PARAMs + n CP_MEM_WRITE submits, fence wait, value check). `m4wifi.sh` (`/extra/m4wifi.sh [noscan]`, wifi tree): own apnhlos (wpss) + own vendor (board.bin -> bdwlan.elf, regdb.bin as runtime symlinks under /lib/firmware/ath11k/WCN6750/hw1.0), 11 hashes, PAS + ath11k_ahb, `/extra/nlscan dev` + wlan0 up + `nlscan scan`. `m4bt.sh` (BT tree, after m4wifi.sh; not run yet): own vendor BT firmware links under /lib/firmware/qca, btqca + hci_uart, `/extra/bthci`. `FIRST-RUN.txt`: the exact first on-phone command and its expected outcomes (copy of
`out-ml/FIRST-RUN.txt`). `./sync-ml-patches.sh` regenerates the numbered patches from the worktree.
